## 主表与展开内容

主表面向当前蛋白对应基因的疾病关联，显示疾病名称/来源编号、遗传方式、来源、原证据分类及争议提示。按疾病展开定义、逐来源断言、HPO表型和文献。临床分类、遗传方式属于相应来源关系，不把不同机构/基因的结论压成单一疾病属性。

| 内容 | 保留与展示 |
| --- | --- |
| 疾病身份 | OMIM/MONDO/MedGen的原生ID、名称、条目类型、别名、外链、带出处定义；缺定义留空，不承诺现有OMIM文件含完整叙述 |
| 基因—疾病证据 | OMIM、ClinGen、GenCC逐来源记录、分类、遗传方式、机构、日期及报告；支持、有限、争议、反驳等均保留，改变解释的提示在主表可见 |
| 疾病—表型 | HPO名称/ID、频率、起病、文献、证据、NOT及aspect；临床表型、遗传方式和其他注释分组，NOT明确标记，完整记录可展开 |
| 基因剂量 | ClinGen HI/TS独立小表，保留报告与日期，不赋给每个疾病或变异 |
| 标识与层级 | 后台保留MONDO等价映射、MedGen联系、未匹配/歧义和层级，支持导航；不当作独立致病证据 |
| 相关变异 | 仅在具体变异—条件关系建立后展示，保留分类、条件集合、review status及来源粒度；目前未执行ClinVar关联 |

ClinGen activity和HPO基因疾病导航明确为汇总/导航，不能当作独立有效性断言。GenCC与ClinGen可能同源，不累加为支持投票，不计算新综合评级。癌症表达/预后复用Expression入口；未确认癌种对应时不按名称硬接疾病。

## 精简与串联

- 默认折叠长定义、同义词、完整表型、文献和机构详情；不在每行重复蛋白/基因名称、数据库说明及长URL。共享词典/元数据只存一次。
- 原始整行payload、解析调试列和未使用的全量参考文本无需照搬网站库；来源标识、记录定位、版本、映射状态及语义限定仍保留。39张上游表不要求一对一成为网站表。
- 保留GenCC编号冲突与共享报告候选；候选不是已完成去重。上游原生表及全部来源记录继续可追溯。
- 查询沿现成关系：accession → gene_protein_link → gene_disease_evidence → disease_entry → 定义/HPO/来源映射。基因关联不代表isoform特异性。
- 疾病以来源ID组织，只有既有unique_exact关系可用于跨来源导航/分组，并保留原ID与断言。共享CUI、同名或本体祖先关系均不构成自动合并依据。
- 变异详情与疾病详情后续共用同一变异—条件关系；不能把基因所有变异放入某病的致病变异列表，也不将VCV总体分类复制为每个疾病的结论。

## 实施依赖

现有六库基础link可用于蛋白的疾病背景，不等待ClinVar。ClinVar条件集合/成员及变异关联、疾病类别锚点另按上游规则落实；旧36类不自动恢复。服务层已落实20张业务表与12个普通视图，不合并不同粒度的科学关系。计数注明来源疾病条目、基因关联或变异条件，不能直接称跨库去重疾病数。
