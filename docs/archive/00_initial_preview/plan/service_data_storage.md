## 数据分层与本地形式

科研正式实体、关系和证据由modules/*/data/curated维护。Web从已确认数据中选择内容，生成适合网站查询的服务表；本轮cleaned身份及同版UniProt选中comment的机械解析例外见[本地构建方案](local_table_build.md)。数据库字段、API返回与页面展示分别确定。默认折叠不删除数据库中的完整注释。

网站服务数据采用Parquet，保存到Web/data/tables，原则上一张逻辑表一个文件。数据优化后直接更新当前文件，不建立Web releases或runs目录。先写临时文件，完成必要核对后替换当前文件，失败不覆盖可用产物。来源自身版本、输入位置和构建时间继续记录。

```text
Web/
├── docs/plan/             # 确认后的方案、表契约与展示规则
├── docs/research/         # 调研、统计及待决设计
├── config/
│   ├── inputs.yaml       # 上游正式输入及来源版本
│   └── tables.yaml       # 表字段与已确认选择规则的配置
├── src/
│   ├── build/            # 网站服务表构建
│   └── database/         # PostgreSQL建表与导入
└── data/
    ├── README.md         # 当前表清单、行数、来源与构建/验证/导入状态
    └── tables/           # 当前Parquet服务表
```

按实际任务创建文件，不预建空表或空目录。科学规则由相应上游模块维护，Web配置引用已确认规则，不另行隐含代表项选择或映射语义。PostgreSQL是查询运行环境，其数据库文件另占存储，不替代本地科研正式数据。

- 开发验证：一个板块的正式输入和服务表准备好后，可以导入开发库，验证查询、API及页面，不必等待所有板块完成。本轮按用户追加授权执行本地数据库创建及导入。
