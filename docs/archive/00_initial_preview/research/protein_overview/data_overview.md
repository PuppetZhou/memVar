## 目的与交互建议

回答三个问题：当前蛋白有哪些数据、各板块有多少可用内容、这些内容来自什么版本。建议用卡片给出数量或覆盖状态，点击进入对应板块明细，并保持计数与明细使用同一对象范围和筛选口径。

## 候选面板内容

| 板块 | 候选指标 | 后续要定义的口径 |
| --- | --- | --- |
| 突变 | 收录变异数、蛋白氨基酸替换数、具有指定预测注释的变异数 | DNA变异、蛋白替换和注释记录分别计数；不能跨粒度相加 |
| 疾病 | 关联疾病数、具有疾病关联的变异数 | 基因—疾病与变异—疾病分开；跨来源疾病是否可去重按正式疾病关系确定 |
| 位点与膜环境 | 已注释位点数、PTM位点数、膜区段数 | 明确序列对象、区段定义、去重键及实验证据/预测范围 |
| 功能与通路 | GO条目数、通路数 | 遵循对应板块已确认展示口径，不将来源证据行数当成独立功能数 |
| 蛋白背景 | 互作伙伴数、表达数据覆盖、QTL关联情况 | 区分伙伴与证据数、表达覆盖与表达量、QTL关联与基因映射 |

首期优先讨论用户点名的突变与疾病，其余卡片按实际价值和数据就绪程度选择，不预设全部上首屏。

## 数据版本如何表达

“各个版本数据的情况”保留为待细化需求：建议首期展示当前网站实际使用的各板块来源版本及更新时间。来源版本与网站更新日期分开，同一板块可有多个来源版本，不伪造单一统一来源版本。

若后续希望对比memVar不同历史版本的蛋白收录变化，再明确对比对象、指标口径和保留方式；本轮没有授权建立历史数据副本。必要的历史统计摘要可讨论用MD记录，沿用当前文件直接更新、不建立Web releases/runs目录的约定。当前历史讨论记录不能自动作为可精确重建旧数据的依据。

## 统计与呈现边界建议

- 建议首屏以当前蛋白条目为范围，涉及残基坐标的指标标出所用序列；是否随isoform切换重新统计后续确定。不可把基因关联数据统一称为canonical特异数据。
- 使用实际进入网站服务数据的内容统计；已收集但尚未选入网站的科研数据如需展示，单独标明状态，不混入可点击的正式数量。
- 数量0、尚未接入、尚未统计及关联未解决应区别表达；没有统计结果不填0。
- 每个指标最终需有唯一计数定义、对象范围、来源和去重键；不将原始记录行数直接当实体数。这里只提出设计要求，具体科学口径在对应板块确认后复用。
- 是否预计算、使用视图或独立汇总表，待指标与访问需求明确后决定；当前不增加新表、历史版本系统或复杂统计框架。

## 后续设计顺序

1. 完成相关板块实体及筛选口径审查。
2. 选定少量核心指标，确认名称、单位、适用对象及空值状态。
3. 明确版本信息是否仅展示当前来源，或需要历史统计比较。
4. 用真实蛋白样例讨论卡片布局和跳转，再设计汇总数据及API。
