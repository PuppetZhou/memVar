# 网站架构整理与可搬迁部署计划

更新：2026-10-06。方向已确认；本次只记录计划，代码修改、GitHub提交和T7搬迁尚未执行。

## 目标与要求

网站仅依赖“网站代码＋独立网站数据包＋运行环境”，运行时不依赖科研 `modules/` 或 PostgreSQL。保持当前前端、后端接口、可视化、数据范围与科学含义不变。

- **规范数据与view**：以实际入库快照为基准，整理Parquet实体表、关系表及DuckDB视图，明确粒度、关联键和读取依赖，统一维护视图定义。AlphaGenome轨道保留HDF5，结构文件保留现有格式；目录、版本和关联信息纳入数据包。不为统一格式重新清洗数据或改成单张宽表。
- **清理代码架构**：删除PostgreSQL运行支持、废弃导入迁移入口及确认无用的旧代码；分清离线数据构建、部署准备和在线查询职责。当前查询结果依赖的SQL转换、排序和数值处理须验证后再简化，不能按名称直接删除。
- **统一配置与路径**：集中管理数据根目录、资源位置和运行参数，包内使用相对位置；部署准备统一完成基础目录重绑定及AlphaGenome裁剪目录接入。保留历史来源路径作为溯源事实，不做全局替换。

## 执行顺序

1. **固定基线**：核对GitHub与本地差异，提交当前可用版本，记录代码与现用数据版本。
2. **本地整理与检验**：完成上述数据、代码、配置整理；形成明确的部署准备、启动和验收入口。使用独立目录验证，不覆盖正在运行的可用数据。
3. **T7搬迁与试运行**：本地通过后，将匹配版本的代码仓库和完整网站数据包复制到T7，从T7代码启动并读取T7数据，完成搬迁验收；保留T7已有原始数据，不执行镜像删除。

完成标准：无科研目录、无PostgreSQL、部署根目录改变时仍可运行；关键接口的字段、数值和排序与基线一致，结构和实际轨道读取正常，现有页面交互保持。T7试运行不能暗中回读本机科研或网站数据。代码、数据版本及验证结果有简明交付记录。

## 本轮边界与讨论机制

- 本阶段做到本地检验和T7打包、试运行；网站润色、安全/防爬升级和正式云端部署留待后续。原始来源恢复与raw到入库全流程规范化另行推进，不将其自动扩展为本次重构。
- 清除冗余前核实依赖，保留唯一原始来源、当前服务必需资产、必要脚本/规则及溯源记录；“旧版本”或“中间文件”的名称不能单独作为删除依据。
- 遇到尚未确认、会影响科学含义、数据精度/格式、唯一副本保留或不可逆删除范围的决定，或超出本计划的重要架构选择时，先说明证据、建议与影响，暂停相关步骤讨论；其余独立工作可继续。常规实现、路径配置和故障修复按已确认目标自行处理，不逐项重复确认。
- 不重跑无关科研流程，不计算SHA-256；核对范围以本次修改和搬迁验收需要为准。
