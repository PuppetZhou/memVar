1. 按用户指定问题读取清单定位及必要基线，核实当前代码/数据；不把旧阶段文字状态作为运行证据。
2. 有未决科学选择时形成依据和取舍；明确要求内的技术实现按授权推进。只有真正需要专题时才新建编号方案。
3. 采用方案写清与00基线的对应关系。只修订受影响内容，上游规则仍在负责模块维护；[plan总索引](../README.md)登记当前适用入口。
4. 实现后验证受影响的数据—API—页面链路，将结果、限制写入01 record；回写原问题状态。完整数据缺口、未匹配与来源缺失不能通过页面隐藏假装完成。
