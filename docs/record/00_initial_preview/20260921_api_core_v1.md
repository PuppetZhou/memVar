# 2026-09-21：基础信息与 Sequence API 初版

范围：实现当前 PostgreSQL 正式服务数据的只读 API，不重新采集、映射或导入科研数据。网站整体建设与页面验收另由网站交付记录维护。

## 实现与接口

代码：[core.py](../../../src/api/core.py)、[sequence.py](../../../src/api/sequence.py)、[db.py](../../../src/api/db.py)、[main.py](../../../src/api/main.py)。依赖：[requirements-web.txt](../../../requirements-web.txt)。

- `GET /api/health`：读取数据库连通性与基础蛋白数据可用性。
- `GET /api/proteins?query=&limit=`：accession、名称、基因名称与历史编号检索；精确 accession/基因名称优先。返回完整 `gene_names`；兼容字段 `gene_name` 仅是首项，不替代完整关系。
- `GET /api/proteins/{accession}/overview`：蛋白身份、已确定的 FUNCTION、按对象保留的补充注释、isoform 声明、外部标识、膜标签、GO、Reactome、定位、Rhea、GtoPdb。
- `GET /api/proteins/{accession}/overview/{section}?limit=&offset=`：`section` 为 `go/pathways/rhea/pharmacology`。GO 可加 `aspect=F/P/C`。各页返回 `items/has_more/limit/offset`；初页分别取 30/15/10/15 项，余项通过分页读取，不改变数据库收录。
- `GET /api/proteins/{accession}/sequence?topology=uniprot`：canonical 序列、PTM、Domains/regions、UniProt 二级结构、膜 TOPO、功能位点以及独立 JSD 数组。`topology_options` 的 `id` 可直接作为 `topology` 参数，包含 DeepTMHMM2 和按来源/方法/原记录/来源序列/role/model 分开的其他膜轨道。
- `GET /api/proteins/{accession}/sites/{position}?limit=&offset=`：当前位点的来源 PTM、UniProt、Pfam、JSD、OPM/MPLID/BioDolphin；PTM 有 `ptm_pagination`。结构接触每个来源展示最多 50 项并返回 `membrane_contacts_has_more`，本版不承诺显示全部结构观察。
- `GET /api/proteins/{accession}/sequence/unmapped?source=&limit=&offset=`：尚无正式 site 连接的来源记录；另兼容 `unmapped-ptm` 路径。包括已发布候选蛋白关联，显式标记 `association_status`。PTMD2 疾病、State、MutationSite 等来源原文在 `details`，引用在 `evidence`，不将来源位置投影到 canonical。

运行入口为 `uvicorn Web.src.api.main:app --host 127.0.0.1 --port 8000`。前端构建后由同一服务提供 `Web/frontend/dist`；路由同时包含其他代理实现的 evidence 与 structure。JSON 与 PDB 响应按需 gzip。

## 展示语义与字段边界

- FUNCTION 默认项严格读取 `protein_function_overview.default_annotation_id`，不自行重选或总结。补充注释保留 `scope_type/scope_label/isoform_ids/mapping_status`，不能将其他 isoform 或未解析对象改为 canonical。
- GO 列表保留 `is_negative/relation/form_id/subject_id/extension/evidence_code/reference`，实验类别只用于排序。slim 使用已有 `protein_go_slim` 正向视图，补充每类的 `contexts`，避免丢失对象和条件；不计算重要性或来源支持总分。
- UniProt 定位保持 `locations[]` 和父级对象；HPA 保留基因级 `main_location/additional_location/enhanced/supported/approved/uncertain`。整行 reliability 不能自动解释为每个定位的相同可靠性。
- 膜标签返回稳定 `label`、可读 `label_name`、`sequence_id`、`supporting_records`；不据缺失轨道推断“无膜区段”。默认 TOPO 仅 UniProt，DeepTMHMM2 明确为预测。
- 所有画上序列的对象限定当前默认 canonical。UniProt 不确定边界保留 `unlocated_features`，不按准确坐标画出。其他来源 TOPO 复用正式 exact 映射；膜接触限定 `mapping_status='mapped'`。
- 膜接触保留来源/目标残基、`is_wildtype_residue` 与映射方法；BioDolphin 的 `PDB/Re-numbered` 两套原编号显式保留，不把两行当作独立证据。PTM 引用保留 `is_current`，不抹去已有的停用状态。
- Pfam 主显示 `ali_start/ali_end`（alignment），同时返回 envelope/HMM 边界，明确 `boundary_type='alignment'`；不把较宽 envelope 作为实际匹配范围。
- PTM marker 仅把同位置、同类型、同来源的记录组织为一个交互标记，保留全部 `record_ids` 与端点角色；二硫键不填满两端之间的残基。
- JSD 保留原值、占有率、缺口比例、非标准残基和同源支持状态，不解释为致病概率。
- API 显式投影，不输出管理员凭据、内部磁盘路径、导入时间或注释日期。稳定来源键可能本来包含来源版本字符串，保留键用于回溯，不将其作为页面日期字段。

## 连接与权限

复用现有 Python 与数据库；只增加缺少的 SQLAlchemy，无新增测试数据库或独立 Python 环境。单 SQLAlchemy 连接池为 5 个连接、最多 2 个溢出连接；参数绑定、15 秒 SQL 超时、默认只读事务，错误响应不回显 SQL 参数。

`python -m Web.src.api.db --setup-reader` 为 `memvar_api` 配置四个 schema 的 USAGE/SELECT 和后续表默认 SELECT；运行时只读取 `Web/data/.api.env`（0600）或显式配置的连接 URL，不读取管理员凭据。为未定位记录的既有候选蛋白查询添加一个 `accession IS NULL` 的 partial GIN 索引，重建库后可由同一入口恢复。没有修改科学筛选或映射。

## 本地部署与输入边界复核（2026-09-21）

本次仅检查现有启动入口、当前产物和同库 API；没有重启运行中的服务，也未新建测试环境。

- `Web/start-local.sh` 通过 `bash -n`；现有 Python 可导入全部七项运行依赖；`.api.env` 权限仍为 0600。默认绑定本机 8000，前端构建检查先于启动。
- 实际数据库身份为 `memvar_api`、非 superuser、`transaction_read_only=on`。health 的 `read_only` 改为读取实际事务设置，不再返回写死值。
- 修复静态 fallback：首页、蛋白深链接、搜索和 About 正常返回 HTML；存在的 JS 返回 JavaScript；不存在的 `.js`、隐藏文件、路径越界及 NUL 请求返回 404，避免把缺失脚本误返回为 index.html。SPA index 使用 `Cache-Control: no-cache`。
- 已定向验证未知 API/蛋白/模型返回 404，越界/非整数位点、非法分页和不支持的拓扑选择返回 422；缺模型仍以 `no_local_model` 空状态返回 200。
- `MEMVAR_DATABASE_URL` 的普通 `postgresql://` URI 自动选择当前使用的 psycopg 驱动。凭据文件缺失/格式不完整通过无敏感内容的 503 表达。
- 结构目录接口和直接模型接口均处理文件读取失败；直接请求损坏模型返回 503，不输出本地路径。通过 TestClient 内存故障注入核对：数据库 OperationalError、缺失连接配置、损坏 gzip 分别返回简洁 503；未停止真实数据库、未改坏真实文件。
- 膜来源选项改为“来源 · 方法 · 记录性质”，同类多记录用 Record n 区分，原记录键/来源序列键保留为详情字段。P00533 的 28 个选项有 28 个不同 ID 和标签；TOPDB 的 Integrated topology 与 Experimental evidence 已明确区分，没有合并记录。
- OPM 位点响应增加 `site_coordinate_basis`，真实样例 A1L3X0:16 为 `sidechain_heavy_centroid`，不能默认称为 Cα 深度。OPM 有符号深度不据此推断胞内/胞外；MPLID 距离与 BioDolphin 配体语义由来源分别表达。

运行边界：启动脚本复用已运行的 PostgreSQL，不负责重新导入或启动数据库；Python 依赖须预先按 requirements 文件安装。本轮没有验证公网部署、TLS、进程守护或并发负载。代码修改需由网站主任务最终统一重启服务生效；这里的 TestClient 验证不冒充运行中旧进程已经加载新代码。
