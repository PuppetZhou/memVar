# 首个公网预览版：进展与后续方向

记录日期：2026-09-21。用户确认当前数据库已通过 **ngrok** 完成初版公网发布，用于向导师分享和收集反馈。此版本作为首个公网预览基线；此前“网站初版、第二版、第三轮”等名称指本地界面迭代，不表示已经发布过多个公网版本。

## 发布状态

- 网站与 PostgreSQL 继续在本机运行，通过 ngrok 提供公网访问；本次没有迁移数据库或本地资源。
- 发布完成依据为用户确认。本轮只更新文档，未重新开启隧道、调整服务或独立验证公网访问；公网地址、有效期及大陆网络实测结果尚未登记。
- 预览依赖本机服务、网络及 ngrok 隧道持续运行。当前定位为短期展示与反馈收集，并非长期托管或并发容量验收。

## 下一阶段（待开展）

1. **收集首版反馈与补齐细节**：以导师实际浏览为依据，记录问题所在页面、筛选条件和预期行为；优先处理可读性、交互、证据解释与已有待验收项。
2. **研究更高分辨率 AlphaGenome 数据**：核查可用原始预测资产及其分辨率、模态和覆盖范围，再确定读取、分层聚合与局部窗口加载方案。单纯放大现有降采样图不能恢复原始细节；如需新增预测或改变数据范围，另行确认。当前实现与限制见[AlphaGenome 方案](../../archive/00_initial_preview/plan/expression_alphagenome.md)。
3. **评估后续数据迁移**：在需要长期稳定访问时，再确定服务器、存储和迁移范围；除 PostgreSQL，还需覆盖结构模型与 AlphaGenome 等本地文件依赖。当前没有启动迁移。
4. **形成长期发布方案**：结合实际访问情况明确域名、运行维护与备份恢复方式。ngrok 作为本次临时入口，不预设为长期部署方案。

## ngrok 8012 故障与恢复（2026-09-21）

- 现象：公网请求到达 ngrok，但连接 `127.0.0.1:8000` 被拒绝。
- 核查：8000 无监听；PostgreSQL 55432 正常，ngrok 本地管理接口仍返回活动隧道。`/tmp/memvar-v2-api.log` 显示旧 Uvicorn 进程正常 shutdown，没有异常堆栈；触发关闭的原因未确定。
- 恢复：使用用户级 systemd 临时服务 `memvar-web-preview.service` 管理网站进程，工作目录为当前项目，继续仅监听 `127.0.0.1:8000`，配置 `Restart=on-failure`、重启间隔 3 秒。没有改动 ngrok 地址、数据库或网站代码。
- 验证：本机和既有 ngrok HTTPS 地址的首页、`/api/proteins/Q12809/overview` 均返回 HTTP 200，内容类型及响应长度一致；服务状态 active/running。本次验证从服务器发起，不代表大陆外部网络验收。
- 运维：`systemctl --user status memvar-web-preview` 查看状态；`journalctl --user -u memvar-web-preview -n 50` 查看日志；`systemctl --user restart memvar-web-preview` 重启；`systemctl --user stop memvar-web-preview` 停止。恢复后日志由 journal 维护。
- 边界：这是临时用户服务，不承诺机器重启或用户会话管理器退出后自动恢复；未配置 ngrok 开机启动。长期运行方案另行安排。
