# memVar 高信息密度展示与交互优化方案（2026-08-24）

> 性质：M18 之后的调研与可执行设计方案，未修改代码。  
> 范围：内容层级、蛋白页四个任务板块、Variant Summary、结构查看、视觉 token、响应式、性能与测试。  
> 科学边界：不合并 ClinVar/COSMIC/预测证据，不生成综合致病性或优先级分数，ThermoMPNN 只表达预测的热力学稳定性变化。

## 0. 结论摘要

memVar 现在的问题不是“缺少数据”，而是同一视觉层同时承载了身份、来源证据、模型预测、频率和外部标识符，导致重点不稳定。本轮不应更换 Next.js/CSS 技术栈，而应在现有数据契约上建立一条稳定的研究路径：

1. 保留当前 **Foundation / Genetic evidence / Molecular context / Network & clinical** 四个研究任务组及其 deep link，重做 sticky nav 的组间层级、配色、icon、active/hover/focus 和窄屏交互；同时收敛首页四张 evidence-journey cards 的等权彩色外观。
2. Variant Summary 从“展开整行才能看”改为 **行内可操作证据入口 + 右侧 drawer/移动端 bottom sheet**。ClinVar、COSMIC 和 Stability 只要出现在主行，就必须是真实 `button`，可独立打开对应 branch；不再要求用户先展开全部详情。
3. 主表默认只显示 6 个信息组；提供列显示选择器、预设和 URL 状态。保留 variant 身份和 protein effect，其余由用户选择分批显示。
4. 结构视图将 M18 的默认 molecular surface 改为 **cartoon/ribbon 主体 + 选中位点 stick/highlight**；默认不显示原子点、CA sphere 或全蛋白 ball-and-stick。结构与序列共享 canonical site selection，支持 chain/fragment、domain、pLDDT 和 variant-density 独立模式。
5. 视觉上使用“中性画布 + 单一主交互色 + 板块细窄定位色 + 数据自有语义色”，图标为导航和操作服务，不代替来源文字或科学定义。

最高优先级是 Variant evidence action strip、branch drawer、列选择器和 ribbon 结构视图；更换整套前端模板、暗色模式和新综合分数均不属于本轮。

### 1.3 不虚构字段的实施前置

- 当前 `VariantItem` 可支持 source presence、AlphaMissense、stability、gnomAD、dbSNP 行内显示；不支持不请求 detail 就展示 ClinVar assertion count/classification 或 COSMIC sample count。
- 最小可行切片可在点击行内 branch 时复用现有 `/variants/{variant_key}?protein_accession=...`，再在 drawer 中只显示所选 branch；这不需要在列表返回全部证据。
- 若要在 button 上显示 exact `ClinVar 3` / `COSMIC 2`，需在离线 summary 增加独立 `clinvar_record_count` / `cosmic_fact_count`；只是记录数，不是证据强度。
- ClinVar 稳定外链仅在实际 branch 保留 VCV/Variation ID/RCV/SCV 之一时生成；优先 VCV/Variation ID。COSMIC 仅在数据契约保留其可公开的稳定 mutation ID 时生成单记录链接，否则只显示站内 branch 和 COSMIC 来源页。

P00533 当前真实接口验收基线为：canonical variants exact **4,385**，其中 ClinVar **3,062**、COSMIC **908**。`7-55019282-G-A` 同时具有 ClinVar、COSMIC 和 ThermoMPNN，应作为“同行三个可操作入口且不合并语义”的固定验收样例。

## 3. 设计原则

1. **任务优先于数据表。** 用户先回答“这是什么”、“变异有哪些证据”、“位点在序列/结构中处于何处”，再进入原始记录。
2. **完成一个小闭环再加一层。** 主行回答 identity + availability；branch drawer 回答 source-specific summary；单 assertion/fact 再回答 provenance 和外链。
3. **来源独立。** ClinVar assertions、COSMIC facts、AlphaMissense、ThermoMPNN 和 gnomAD 不共享分类色、不投票、不合并为“variant status”。
4. **颜色不承担唯一语义。** 来源用 icon + text + border；classification 用 text + tone + symbol；stability 用 signed number + zero-axis glyph + direction text。
5. **主行出现即可操作。** 出现 ClinVar/COSMIC/Stability 就必须可通过鼠标、Enter/Space 和触摸进入详情。
6. **默认密度不等于字号缩小。** 通过减少默认列、字段分组、drawer 和虚拟化降负，不将正文压到 12 px 以下。
7. **结构主体先呈现形状。** 默认 ribbon/cartoon 显示二级结构；原子级表现只在用户选中局部位点后出现。
8. **状态可恢复。** active section、variant filters、columns、selected variant branch、site、structure fragment/color mode 都可在 URL 恢复，同时避免在 URL 写入大型原始数据。

### 4.1 保留四个任务组，加强辨识度

| 板块 | 包含现有 sections | 首层回答 | 定位色/图标（不改变数据色） |
|---|---|---|---|
| Foundation（现有） | Overview、Sequence、Structure | 蛋白身份、canonical sequence、位点/域/PTM 与 3D 上下文 | Indigo `#3F51B5` / `Fingerprint`, `ScanLine` |
| Genetic evidence（现有） | Variants，内含 ClinVar、COSMIC、prediction、population | 哪些 genomic variants 映射到当前蛋白，各来源说了什么 | Coral `#B9473F` / `Dna`, `Database` |
| Molecular context（现有） | Anatomy、Expression、QTL、AlphaGenome | 组织、表达和调控证据的来源覆盖 | Teal `#0F766E` / `Activity`, `ChartSpline` |
| Network & clinical（现有） | Interactions、Diseases | 网络证据与来源独立的疾病 assertions | Amber `#9A6700` / `Network`, `FileHeart` |

布局规则：

- 桌面端左侧 220–240 px sticky task rail，中间主内容，打开 site/variant branch 时右侧显示 380–440 px drawer。
- 1024–1199 px 左侧 rail 收为顶部 sticky segmented navigation；drawer 覆盖右侧但不改变主内容宽度。
- ≤ 767 px 使用“Sections”目录 button + bottom sheet；主表允许局部横滚，但页面级不得横向溢出。
- sticky nav 中的四组使用 3–4 px top/left accent、组 icon、组标题和 active section marker 区分；内容面大面积仍是白/中性背景，避免“四个高饱和彩色容器”。
- 首页四张 journey cards 与 sticky nav 共用组名、icon 和定位色，但视觉上强调“01→04 的研究顺序”：第一张为主入口，后三张降一级，不再用四种等权高饱和色争夺注意力。
- 每个板块的固定阅读次序：`Takeaway → exact coverage/counts → primary visual/table → details → provenance/limitations`。

### 4.2 交互状态

```text
idle
  └─ hover/focus            图标底座 + border + 文字同时变化
       └─ activate          更新 URL，打开 branch drawer
            ├─ loading       保留行高，button 内 spinner + 文字
            ├─ ready         持续 active outline，drawer 标题与触发器一致
            ├─ empty         显示“当前 release 无记录”，不显示 0 值伪记录
            └─ error         仅该 branch 错误，可 Retry，不收起主表
close/Escape
  └─ 焦点返回原 evidence button，保留表格滚动与筛选
```

## 5. Variant Summary 详细规格

### 5.1 默认主行

默认只保留：

1. Variant：HGVSp（主）+ genomic key/build（次）；
2. Protein context：consequence + canonical/isoform + position；
3. Evidence：ClinVar/COSMIC/其他 source action buttons；
4. Predictions：AlphaMissense + ThermoMPNN，强制标注 `Predicted`；
5. Population：gnomAD AF；
6. More：dbSNP 与行级完整详情。

主行不显示“综合临床状态”。多个 ClinVar assertions 存在时，button 只显示 `ClinVar` 或 exact `ClinVar · N records`，不显示经投票得出的 Pathogenic/Benign。

### 5.2 行内 evidence action strip

| 入口 | 主行可见内容 | 点击后的站内内容 | 外链 |
|---|---|---|---|
| ClinVar | `Database` icon + ClinVar + presence/exact count | drawer 直接激活 ClinVar tab：顶部 exact assertions/conditions/review states，下方按 RCV/condition 分组的独立 assertions | 每个记录在有稳定 ID 时显示 `Open VCV/RCV in ClinVar` |
| COSMIC | `Orbit`/`Database` icon + COSMIC + presence/exact fact count | drawer 直接激活 COSMIC tab：sample count、disease categories、MONDO、CGC tier/roles，固定显示 gene-level caveat | 只有存在合法稳定 ID 才直连；否则给 COSMIC 来源页，不猜测 ID |
| Stability | `Activity` icon + signed ΔΔG + kcal/mol | drawer 直接激活 Stability tab：Ref→Alt、exact ΔΔG、direction、model、PDB fragment、解释限制 | 不需外部 ThermoMPNN API；PDB 下载使用现有站内资产路径 |
| All details | `ChevronRight` + All evidence | 完整顺序：Identity/Effects → source tabs → Predictions → Population/IDs | 各 branch 内独立外链 |

按钮必须有 40×40 px 最小鼠标命中区，触屏为 44×44 px；icon 只是辅助，始终保留来源文字。`aria-label` 包含 variant 身份，`aria-expanded`/`aria-controls` 反映 drawer 状态。

### 5.3 drawer 信息层级

```text
[HGVSp]  [genomic key]                                  [Close]
Canonical/isoform effect · position · consequence

[ClinVar N] [COSMIC N] [Stability] [Protein effects] [Population]

Selected branch takeaway
  exact counts / exact value / availability

Primary fields
  2–4 个强调数值或状态 tile

Source records
  summary-first cards; each record independently expandable

Source context and interpretation limits
  source / release / record grain / stable external links
```

- source tabs 只显示有数据或有明确 empty 语义的 branch。
- 切换 tab 不重复请求同一 variant detail；用 accession + variant_key 作 client cache key，换 accession 时 abort/清空。
- 大量 ClinVar assertions 时分页或以 condition group 有界折叠；不在一次 drawer 打开中建立无界 DOM。
- generic `DetailFields` 仅可作未识别字段的调试降级；公开 ClinVar/COSMIC/Effect 使用显式 field order 和 typed view model。

### 5.4 列显示选择器

预设：

- `Balanced`(默认)：Variant、Protein context、Evidence、Predictions、Population、More。
- `Clinical review`：Variant、Protein context、ClinVar、COSMIC、gnomAD、IDs。名称只表示列集，不表示 memVar 临床判读。
- `Protein science`：Variant、Protein effect、Consequence、AlphaMissense、Stability、Site。
- `Custom`：用户选择后自动进入。

规则：

- Variant 身份列和行 actions 不可同时隐藏；至少保留一个可打开详情的入口。
- 选择器使用 checkbox list + `Show all / Reset to preset`，显示 `6 of 10 columns`；支持 drag/reorder 可放 P1，P0 先做显示/隐藏。
- URL 使用短预设 `variant_view=balanced|clinical|protein`；Custom 只存列 key，不存颜色/宽度。
- 桌面宽表使用 sticky identity column/header；窄屏优先转为一行两层的 list-row，而不是继续缩小到 940 px 的宽表后强制横滚。

### 5.5 字体和配色

- HGVSp 使用 16–17 px/700 sans；variant key、rsID、坐标用 13–14 px mono；字段值 14–15 px；metadata 不低于 13 px。
- ClinVar button 使用 indigo outline，只有单个显式 assertion card 内部使用 pathogenic/benign/conflict tone。
- COSMIC button 使用 violet/slate outline；不用红色表达 sample count 或 CGC tier。
- Stability 使用蓝（negative predicted stabilizing）/中性（small）/琥珀（positive predicted destabilizing），避免使用 ClinVar pathogenic 的 coral/red。
- 无数据用 `— Not available/not predicted`，不用淡灰 0。

## 6. 结构视图规格

### 6.1 默认表现

- 默认 `representation=cartoon`，helix 使用稳定管状/带状轮廓，beta sheet 使用 arrow ribbon，loop 使用较细 tube。
- 默认不渲染 atom spheres、CA nodes、全局 sticks 或原子点；这些仅在选中 residue 局部环境时显示。
- surface 作为用户可选的 `Surface` 模式，不再为默认；手机或低端 GPU 不自动加载 surface。
- 背景使用中性蓝灰 radial stage，模型与控件对比达 AA；不生成膜平面、配体或复合物。

### 6.2 配色和注释模式

1. `AlphaFold confidence`：使用官方 pLDDT 四档，默认建议模式，图例说明 higher is better 且非 B-factor。
2. `Sequence variant density`：复用 Sequence 的六档 canonical variant-count 色阶，仅表示记录数量，不表示致病性。
3. `Domain/chain`：用于导航的确定性分类色；图例给 chain ID/domain label/source。只有现有数据能安全映射到 fragment 时显示 domain mode。
4. `Selected evidence`：不是全蛋白配色模式，而是 overlay；selected residue 用高对比 outline + stick，partner/covalent endpoint 使用第二 shape/label。

同时只有一个主 color mode；selected overlay 可叠加，图例必须分开。

### 6.3 与序列/变异的联动

- Sequence residue、Selected Site dossier、Variant row 和 Structure 使用同一 `canonical_position` selection。
- Variant 行的 `View in structure` 只在 canonical effect 可定位且位点落在当前/available fragment DBREF range 内时启用。
- 点击 3D residue：高亮对应 sequence residue，更新 `?site=N&structure_fragment=F1`，打开 Selected Site dossier；无法映射时显示 `Not mapped to canonical coordinate`。
- 点击 domain/chain 只高亮范围，不把 fragment local residue number 当作 canonical number。

### 6.4 控件和可访问性

- 主 toolbar：Reset、Spin/Pause、Fullscreen、Download；都用 Lucide icon + 可见文字。
- 次 toolbar：Fragment/chain、Representation、Color by；带当前值，收入 `View options` disclosure 以降低噪声。
- Canvas/WebGL 提供同步的文字 readout：current fragment/range、selected site、color mode、model/version。
- 无 WebGL/surface 失败时保留 fragment metadata、canonical range、pLDDT/variant summary 和 PDB download。
- `prefers-reduced-motion` 关闭 spin 默认动效；Spin 从不自动启动。

### 6.5 性能

- 继续 `next/dynamic({ssr:false})` 且只在结构 section 进入视口或用户打开时 import 3Dmol。
- fragment 切换 abort 旧 fetch，remove model/surfaces，清理 ResizeObserver/spin；现有清理合同保留。
- 默认 cartoon 比 VDW surface 成本低；Surface 为用户显式请求，可显示进度和 cancel。
- 长蛋白不拼接 fragments；一次仅加载一个 fragment。

## 8. 前端架构深化建议

以下使用 module/interface/implementation/depth/deep/shallow/seam/adapter/leverage/locality 的统一术语。目标不是把大文件机械拆小，而是把多个调用者都必须理解的状态规则放进一个 **deep Module**。

| Module | 窄 Interface | Implementation | Depth / leverage / locality |
|---|---|---|---|
| `VariantEvidenceWorkspace` | `open({accession, variantKey, branch, trigger})`, `close()`, `activeBranch`, `status` | detail fetch/abort/cache、branch tab、URL、drawer/bottom-sheet、focus return、empty/error | 一个 Interface 服务 ClinVar/COSMIC/Stability/All details；高 leverage，请求和焦点错误集中在一个 locality；**Strong** |
| `VariantTableView` | `preset`, `visibleColumns`, `toggleColumn`, `reset`, `serialize` | 列依赖、必选列、响应式预设、URL/local preference | 将主表从布尔 props 组合中解放；列选择器、table header 和 mobile rows 复用同一 Interface；**Strong** |
| `SourceBranchPresentation` | typed source records + source context + stable links | ClinVar/COSMIC 显式 field order、record summary、link adapter、caveat | 取代 generic `DetailFields` 在核心 source branch 的 shallow 展示；提升科学语义 locality；**Strong** |
| `StructureSelection` | canonical site/range、fragment、color mode、representation | DBREF mapping、3D selection、sequence/URL sync、not-mapped state | sequence、drawer、variant 和 viewer 共享一个 seam；一个 mapping Implementation 付费，四处获得 leverage；**Strong** |
| `ProteinTaskLayout` | task groups + section manifest + availability | scrollspy、desktop rail、mobile menu、lazy mount、hash offset | 将四板块导航和加载策略放在一个 locality；避免 `protein-overview.tsx` 继续线性增长；**Worth exploring** |
| `ExternalRecordLink` | typed `{source, idKind, id}` → link/null | ClinVar VCV/RCV/SCV/Variation ID、COSMIC 合法 ID、encoding、allowlist | 已有两个来源 adapter 才是真实 seam；防止多处字符串拼 URL；**Worth exploring，待 COSMIC ID 合同确认** |

`VariantEvidenceWorkspace` 与 `VariantTableView` 不应合并：前者管“查看哪个证据”，后者管“表格怎样显示”，它们的状态生命周期和测试表面不同。

不建议：

- 一个将 ClinVar、COSMIC、gnomAD、AlphaMissense、ThermoMPNN 塞进统一 nullable schema 的“Evidence Module”；它的 Interface 会和 Implementation 一样复杂，是 shallow。
- 为每个 icon/button 创建 pass-through 文件；按 deletion test，删除后复杂度不会重新出现在多个调用者，因而没有 depth。
- 为仅有一种 3Dmol Implementation 创建假的多 viewer adapter seam；“一个 adapter 只是假设 seam”。

## 10. 验收标准

### 10.1 内容层级

- 3 秒扫描内可辨识四个任务板块，且不需用颜色猜科学意义。
- 每个 section 先显示 takeaway/counts，再显示控件、图表、详情和 provenance。
- 主文字、字段值、metadata 三层对比明确；公开内容不以连续小字号呈现。

### 10.2 Variant

- 主行出现 ClinVar、COSMIC、Stability 时，三者均可独立点击/Enter/Space 打开对应 branch。
- P00533 总数保持 canonical variants 4,385 / ClinVar 3,062 / COSMIC 908；`7-55019282-G-A` 一行中同时显示三个可操作入口，且三者分别打开独立 branch。
- 用户不经过“展开整行”也能看到 ClinVar assertion、COSMIC fact 和 exact ΔΔG。
- 关闭 drawer 后焦点返回原按钮；页面滚动、表格筛选不丢失。
- 列选择器可在不刷新数据页的情况下切换，并可通过 URL 恢复预设。
- ClinVar classification 只来自单个明确 assertion；COSMIC/CGC 不获得 pathogenic tone；ThermoMPNN 始终显示 unit/model/非临床说明。
- 外链只由类型化稳定 ID 生成；无 ID 显示站内证据，不猜测 URL。

### 10.3 Structure

- 初始结构是可辨识的 cartoon/ribbon，不显示全蛋白原子点或 ball-and-stick。
- pLDDT/variant density 互斥切换，图例文案和颜色同步，无混用。
- 选中 canonical site 后局部 residue 以 stick/highlight 显示，序列、drawer、URL 同步；越界/无法映射显示明确状态。
- fragment 数字排序、DBREF canonical range、PDB download、no-WebGL/error/empty 降级全部保留。

### 10.4 响应式、可访问性和性能

- 1440/1024/768/390 px 无页面级横向溢出；390 px 可完成列预设、打开三种 branch、关闭并返回焦点。
- 所有 hover 信息可由 focus/click/touch 获取；所有 icon action 有文字或 accessible name；焦点指示对比达 AA。
- 默认首屏不加载 PDB、variant detail、COSMIC/ClinVar child rows、AlphaGenome tiles 或火山图 points。
- P00533 protein page 默认仅显示 10–12 条 variant summary，不再因 compact 模式加载 50 行形成约 26,722 px 长页；精确总数仍持续可见。
- 同一 variant 的 branch 切换不重复下载 detail；切换 accession 会 abort 旧请求并清空。

## 12. 风险与缓解

| 风险 | 后果 | 缓解 |
|---|---|---|
| 在 list endpoint 加入完整 ClinVar/COSMIC rows | payload 膨胀、行乘法、来源语义混合 | 列表只给 presence/exact independent counts；点击后再取 detail |
| 用 source badge 颜色暗示结论 | COSMIC/预测被误解为临床证据 | source 只表达来源；classification 色只在 ClinVar assertion 内出现 |
| 为 COSMIC 猜测链接 | 错链、许可风险 | typed ID allowlist；无 stable ID 不做单记录外链 |
| ribbon 端不能显示局部原子 | 用户无法看位点环境 | 默认 ribbon，selected residue 才局部 stick/sphere；表现分层而不是二选一 |
| 四板块变成四个巨大彩色容器 | 页面更碎、对比更差 | 仅使用定位条/icon/kicker，内容面保持中性 |
| drawer 与 Selected Site drawer 冲突 | 两个右侧面板重叠 | 统一 workspace shell，同时只显示一个 contextual drawer；内部切换 site/variant mode |
| 一次性更换前端模板 | 现有科学交互回归面太大 | 保留 Next.js/CSS/Lucide/3Dmol，按纵向切片深化 Module |

## 13. 明确不做

- 不更换 Next.js 为 Vite，不为模仿 CATVariant 引入 Tailwind/Radix 全套重构。

- 不把 COSMIC sample count 解释为癌种频率，不把 CGC tier/role 解释为 variant pathogenicity。
- 不把 ThermoMPNN 解释为 fitness、function、benefit/harm 或临床证据；不改变 `kcal/mol` 和正负号语义。
- 不将 isoform 坐标用 offset 强制投影到 canonical sequence/structure。
- 不默认渲染全原子点、ball-and-stick、厚 surface、配体、膜平面或伪造复合物。
- 不在运行时调用 ClinVar/COSMIC/AlphaFold 外部接口；外部站点只用稳定 ID 导航。
- 不修改 `View/`，不在生成数据中手工补字段，不为缺失证据生成示例值。

## 15. 建议的交付顺序

1. 先完成 P0-A：不改 ETL 即可让 ClinVar/COSMIC/Stability 可点、直达站内 branch，直接解决用户最明确的交互问题。
2. 再完成 P0-B：用列预设与窄屏 list-row 解决高信息密度，避免在现有 1060/940 px 宽表上继续加列。
3. 独立完成 P0-C：恢复 ribbon 主体、局部原子细节和 site 联动，保留现有 PDB/DBREF/配色合同。
4. 在三个纵向切片验收后，再做四板块总布局与 lazy mounting，避免在基层交互尚未稳定时同时重排整页。
5. 最后基于真实 schema 补 exact counts 和 stable external links；不把“图标可点”与“必须先有外部直链”绑定，站内 branch 本身就是完整的第一层交付。

这一顺序可在不更换技术栈、不破坏旧里程碑和不改变科学语义的前提下，先解决“用户看见了证据，却不能直接进入证据”这个最大的界面断点。
