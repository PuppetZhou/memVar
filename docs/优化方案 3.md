## 0. 决策摘要

本阶段不应把主要精力放在更换前端模板或更换 PDB viewer，而应先解决三个高杠杆问题：

1. **Sequence 从“逐 residue 的视觉墙纸”改为 screen-space 多尺度表达。** 当前代码已将 overview mark budget 限制为 48–96；放大后进入 cluster，只有近距离视图才恢复单 residue 位点。减少柱数不是删数据，tooltip、点击和下钻仍保留精确计数。
2. **建立分层 icon system。** Lucide 负责操作，Healthicons 负责 tissue/system 小图标，EMBL-EBI anatomogram 负责 ontology-aware 人体交互，BioRender/NIH BioArt 负责少量完整科研插图。不要给 47 个 tissue 各画一套复杂插图，也不要用一个器官图标同时表示来源、数值和交互状态。
3. **采用 Mol* 的 AlphaFold-style surface。** 默认以 pLDDT molecular surface 建立整体空间方向；选择 residue 后显示 target 与 5 Å surroundings 的原子级 ball-and-stick，并与 Sequence/URL 共用同一 selection。PyMOL 只适合离线生成高质量静态图，ChemDraw 只适合未来的小分子/PTM 2D 化学结构。

配色不再以“所有区域都是淡蓝 card”组织页面，而采用：

- 中性 canvas/surface 保证阅读；
- 四个研究任务组各有一个强识别主色；
- 每个 section 使用同色系的深色标题、实色 icon tile、明确 border/rail 和低比例 tint；
- 科学数据色与 UI 板块色分离；
- 颜色、shape、icon、文字共同表达，不让颜色成为唯一信号。

下一阶段应让 **GEN 与其余 tissue controls** 完整复用既有 tissue visual mapping，并继续 EBI anatomogram 与用户统一生成的 BioRender 科研图。Mol* 已经落地，仅需在真实 GPU 浏览器完成 picking/focus 人工验收。

## 1. 当前问题的量化基线

### 1.1 为什么 variant 柱会失去信息量

2026-08-24 对当前本地 API 和生成数据的只读审计：

| 蛋白 | canonical length | canonical drawable variants | occupied variant sites | 结果 |
|---|---:|---:|---:|---|
| P00533 | 1,210 aa | 4,381 | 1,190（98.3%） | 全长逐 residue 柱几乎每个位置都有数据，必然形成连续色墙 |
| Q8WXI7 | 14,507 aa | 42,517 | 14,015（96.6%） | 更长蛋白中逐 residue 柱无法被眼睛逐项分辨 |

P00533 同时还有：

- strict ClinVar P/LP presence：87 个 canonical drawable variants；
- PTM：136 records、129 sites、11 types；
- ThermoMPNN：2,700 distinct substitutions、1,117 canonical sites；
- secondary-structure intervals：146 条（Helix 56、Beta strand 76、Turn 14），已进入 overview API 与 Sequence UI。

Q8WXI7 的浏览器验收确认：14,507 aa 下保持 aggregate view，variant 为 42,517 records / 14,015 sites，PTM 为 823 records / 764 sites；没有错误进入 per-residue detail。

因此当前 Sequence 的问题不是数据不足，而是概览层错误地把“精确数据粒度”直接当作“显示粒度”。CATVariant 截图中较少的柱本质上是 screen-space bins；memVar 应采用相同原则，但保留自己的 source semantics、canonical coordinate 和 site dossier。

### 1.2 当前已有能力

- `/sequence/overview?bins=N` 已返回有界 `density_bins`，包含每 bin 的 variant count、PTM count、JSD mean/min/max；不是从零开始建设。
- 前端已有 full-length navigator、range 输入、zoom/pan、URL site/range、Canvas 高密度绘图和 Selected Site dossier。
- Structure 已使用 Mol* 5.11 动态加载本地 PDB.gz，默认显示 pLDDT molecular surface，并提供 DBREF 校验、residue focus、WebGL/error fallback。
- `anatomy_crosswalk.json` 已有 47 个标准区域，其中 46 个有 UBERON ID；它应继续作为 tissue display identity 的真源。
- 当前缺口是 display architecture，而不是重新做数据整合。

## 2. 高信息密度页面的识别模型

### 2.1 三个时间尺度

页面应让用户在不同停留时间内获得不同答案：

| 时间 | 用户应能回答 | UI 责任 |
|---|---|---|
| 3 秒 | 这是哪个蛋白？哪些研究板块有数据？当前选中了什么？ | protein identity、四任务组、coverage glyph、selected context |
| 30 秒 | variant/PTM/domain/stability/tissue 分布在哪里？哪里值得放大？ | summary visualization、显著 cluster、独立 legend、显式 buttons |
| 3 分钟 | 某一个 site、source、tissue 或 record 的原始证据是什么？ | drawer/dossier、source-specific fields、raw values、stable links |

不要让 Level 3 的原始字段占满 Level 1；也不要在 Level 1 用“综合分数”替代 Level 3 的来源事实。

### 2.2 五层 disclosure

```text
Level 0  Persistent context
         accession · gene · canonical length · current site/range · active filters

Level 1  Section summary
         one takeaway · exact coverage/counts · 1–3 primary actions

Level 2  Interactive overview
         binned tracks · heatmap · anatomogram · pLDDT molecular surface

Level 3  Focused detail
         selected site/tissue/source drawer · bounded rows

Level 4  Raw evidence
         source records · provenance · external stable link · download
```

### 2.3 “看起来可点”的统一语法

| 元素 | 静态形态 | 交互形态 | 禁止做法 |
|---|---|---|---|
| Button/action | 有边框或实色底座、icon + 动词、≥40 px 命中区 | hover、focus ring、pressed/selected、loading | 只有文字变色；静态 badge 冒充 button |
| Filter chip | outline + count | `aria-pressed`、选中后实色边/浅底、可一键 clear | 用 legend 看起来可点但实际上不可点 |
| Data glyph | shape + color + legend | hover/focus/click 显示 exact values | 只有颜色、没有文字或 shape |
| External source | source name + `ExternalLink` | 新窗口说明、stable ID | 用来源 logo 代替来源文字；猜测 URL |
| Selected item | 2–3 px outline + vertical locator +文字 readout | Clear/Focus selected | 只靠轻微背景色 |

## 3. PDB/AlphaFold viewer 决策

### 3.1 结论

**采用 Mol* 5.11，默认展示 AlphaFold-style pLDDT molecular surface，不再使用 ribbon/cartoon 作为主体。**

Mol* 直接在浏览器中加载网站本地 PDB.gz，关闭内置侧栏，仅保留 memVar 自己的工具栏、状态、legend 和下载入口。整体 surface 用于空间方向，选中 residue 后使用 Mol* 原生 Structure Focus Representation 显示 target 与 surroundings 的原子级 ball-and-stick，并由 camera focus 定位；因此不会把整个蛋白变成难读的原子点云。[Mol* instance 文档](https://molstar.org/docs/plugin/instance/) [Mol* selection 文档](https://molstar.org/docs/plugin/selections/)

### 3.2 工具角色矩阵

| 方案 | 适合的角色 | Sequence/residue 联动 | 代价 | 本阶段决策 |
|---|---|---|---|---|
| 3Dmol | 轻量 protein viewer | 可 picking/select，但默认 cartoon 不符合本轮产品方向 | 迁移后不再保留双栈 | 已移除 |
| Mol* 5.11 | AlphaFold-style surface、residue loci/focus、未来结构分析 | Loci、selection、focus 与 Sequence 联动完整；DBREF mapping 仍由 memVar 维护 | bundle/state 较重，采用动态加载控制首屏 | **当前实现** |
| NGL | 通用 WebGL molecular viewer | 可 picking/select，但产品增益不如 Mol* | 仍需重写，收益有限 | 不迁移 |
| PyMOL | 离线 publication-quality ray-traced image | 无稳定第一方 browser embedding | 实时服务会增加 OpenGL/Python/进程池/缓存 | 仅离线静态图 |
| ChemDraw JS | ligand、lipid、modified residue 的 2D chemical depiction | 不支持 protein PDB residue/sequence | 领域不匹配 | 不能替代 PDB viewer |

Mol* 提供结构 loci、selection、focus 与 representation 管理；AlphaFold Server 的结果页也使用 Mol*。因此它比 PyMOL/ChemDraw 更适合作为浏览器内蛋白结构栈。[Mol* display 文档](https://molstar.org/viewer-docs/managing-the-display/) [AlphaFold Server result page](https://alphafoldserver.com/fold/5825a3e4ed760d3a?golgi=true)

PyMOL 官方定位仍是桌面 molecular visualization/rendering 产品，适合生成静态高质量图片，不是浏览器嵌入组件。[PyMOL 官方站](https://www.pymol.org/)

ChemDraw JS 是 2D chemical structure/reaction sketcher；它可服务未来的小分子详情，但不能显示 protein ribbon 或 canonical residue selection。[ChemDraw JS 官方说明](https://revvitysignals.com/sites/default/files/2024-12/rs-faq-ChemDraw_JavaScript.pdf)

### 3.3 下一步 3D 交互

**已落地的范围：**

1. Sequence 选择 canonical site 后，`StructurePanel` 会寻找覆盖它的 AlphaFold fragment 并自动切换，不拼接 fragment。
2. `structure-colors.ts` 用已验证 DBREF mapping 完成 canonical position 与 fragment local residue 的双向转换；不完整、越界或非整数 mapping 返回 `null`，不猜位置。
3. Mol* picking 读取被点击 residue 的 `auth_seq_id`；回调会写入 `?site=N`、删除 `range`，从而同步 Sequence、Selected Site dossier 和 Variant filter 的共享 state。同一 residue 再次点击会清除。
4. Viewer 外有 selected readout、`Focus selected` 和 `Clear`；默认主体是 pLDDT surface，只有 focus target 与 5 Å surroundings 使用原子级 ball-and-stick。

**已验收与后续改进：**

1. shared selection、fragment coverage、URL 往返、DBREF residue mapping 合同已通过；headless Firefox 已验证 no-WebGL fallback 和无 mapping 的明确状态。
2. **唯一未闭合的结构交互 QA**：在有 GPU/WebGL 的真实浏览器中人工验证 surface picking、自动 fragment switch 与 target/surroundings focus；当前无 framebuffer 的 headless 环境不能证明 GPU picking。
3. 后续若加入距离测量、配体或非共价相互作用，应继续使用 Mol* 的受控 representation，不恢复 ribbon-first 视图。
4. PyMOL 仍可在数据构建阶段生成固定视角 pLDDT WebP/PNG，作为 loading placeholder、无 WebGL fallback 和报告图片；不建实时 PyMOL service。

### 3.4 Mol* 后续分析能力触发条件

Mol* 基础 viewer 已完成。下列需求至少出现两项，再扩展为结构分析工作台：

- residue surroundings、氢键/非共价相互作用或距离测量；
- 实验 PDB assembly、ligand、water、validation 或 electron density；
- 多结构 alignment、motif、超大 assembly 或 BinaryCIF streaming；
- PAE/domain/annotation 与 3D 多视图工作台；
- 3D 从 evidence module 升级为主要分析入口。

扩展必须继续验证本地自托管、动态加载、PDB.gz/mmCIF 格式、canonical fragment mapping、bundle gzip 和不依赖运行时外部 API。

## 4. Tissue icon 与 anatomogram 体系

### 4.1 不采用“一 tissue 一复杂插画”

47 个标准区域全部使用独特、多色、细节丰富的器官插画，会产生三个问题：

- 20–24 px 下细节不可辨认；
- granular tissue、cell、fluid、whole-organism context 很难对应单一器官；
- Anatomy、Expression、GEN、QTL 若各自推断分类，会发生同一 tissue icon 漂移。

### 5.1 核心原则：数据粒度与显示粒度分离

CATVariant 的“少柱子”应该理解为聚合，不是删除位点。memVar 的显示规则：

| viewport 范围 | Variant | PTM | Sequence/position |
|---|---|---|---|
| Full/large（>600 aa） | 48 mobile / 64 standard / 80–96 wide screen bins | cluster count + dominant type glyph | 只显示主 coordinate ticks |
| Medium（121–600 aa） | 每 8–12 px 一个 adaptive bin/cluster | cluster 或非重叠 lollipop | 增加 local ticks，仍不显示全部字母 |
| Detail（≤120 aa） | 单 residue bar/lollipop | 单 site glyph | 显示 residue letters、exact position |
| Focus（≤40 aa） | 单 variant/site detail + selected dossier | exact modification records | 键盘逐 residue inspect |

阈值最终按可用像素宽度而不是固定设备名决定；overview mark budget 可从 `clamp(floor(plotWidth / 20), 48, 96)` 起步。只有每个 residue 至少获得约 6–8 px 时才恢复独立 site glyph；任何层级都保留 `Showing/aggregated X records across Y residues`。

### 5.2 Variant density

#### Overview

- 使用已有 `density_bins.variant_count`，默认约 64 bins；不再遍历 1,210 或 14,507 个 residue 直接画细柱。
- 柱高使用 `sqrt` 或 `log1p` 单调变换，tooltip 显示 raw variant count、occupied sites、bin canonical range。
- 主体用 `golden-orange #EE9B00`；strict ClinVar P/LP presence 用 `oxidized-iron #AE2012` 的细顶段或顶端 triangle，并明确写 `explicit ClinVar P/LP presence, not consensus`。
- 点击 bin：zoom 到该 canonical range；Enter/Space 同样可用。
- legend chip 既然支持筛选，就必须是真实 button；若只是说明，就不得使用 button 造型。

#### Medium/detail

- medium 显示 cluster；圆形 count badge 放在局部峰值，不在每个 bin 都放数字。
- detail 恢复每 residue 独立柱；selected site 使用垂直 locator 和 halo。
- consequence stack 只有在后端新增 source-independent consequence-family bin contract 后才做；不能从 ClinVar/COSMIC classification 猜 consequence，也不能复制 CATVariant 的类别而没有数据合同。

### 5.3 Domain、topology 和 secondary structure

当前 feature data 的 secondary structure 已进入 overview API 与 Sequence renderer：

- Domain：较高的圆角 interval、橙色实底或低对比斜纹，长区间显示短 label；
- Transmembrane：dark teal narrow band + diagonal membrane texture；
- Topological region：细线/低饱和区间，避免与 Pfam domain 同权；
- Helix：圆角 capsule；
- Beta sheet：朝 C-terminal 的 arrow；
- Turn/loop：细圆弧或短 green rounded segment；
- secondary structure 放在 PTM 同一大组但独立 lane，保持 canonical alignment。

区间重叠继续使用最多 2–3 lanes，超出显示 `+N`；点击 interval 打开 range dossier，而不是显示无法阅读的全文 label。

### 5.4 PTM glyph grammar

全长视图不再使用密集的窄矩形。使用 shape + color 双编码，并将低频类型归入可解释 family；raw `ptm_type` 在 tooltip 保留：

| PTM family | shape | 建议色 |
|---|---|---|
| Phosphorylation | circle | `#457B9D` |
| Glycosylation | diamond | `#0A9396` |
| Ubiquitin/SUMO-like | hexagon | `#7B95C6` |
| Acetylation/methylation | rounded square | `#CA6702` |
| Lipidation | triangle | `#67A583` |
| Proteolytic/other | ring + center dot | `#C85E62` |

- Full scale：一个 bin 最多绘制 1 个 dominant shape + `+N` mixed-types badge；bin 总高度/size 表示 record count。
- Medium：同位点多 PTM 以最多 3 个同心/并列 shape 表达，更多显示 `+N`。
- Detail：单 site lollipop；tooltip 显示 raw type × count、source、canonical residue。
- 缺失和 zero 不画；没有数据使用明确 empty message。

### 5.5 Stability 的表达

当前 overview 已以“分布和方向”表达 stability，而不是将其画成连续实验信号：

- 零轴固定且更醒目；negative 在轴下、positive 在轴上。
- 每 bin 显示 median line + IQR ribbon；hover/focus 时显示 min/max whisker。
- 缺失 bin 必须让 ribbon/line 断开；不得过滤缺失点后跨空白区生成平滑连线。
- negative predicted stabilizing：`#005F73`；near zero：中性 slate/vanilla；positive predicted destabilizing：`#CA6702 → #AE2012`。
- 文案始终带 `Predicted ΔΔG (kcal/mol)`；红/橙不得被解释为 ClinVar pathogenicity。
- 全长用 binned distribution；detail 只显示有 prediction 的 residue。
- 只有选择一个 site 后，才在 dossier 中用 20-slot substitution matrix/radial glyph 展示该 reference residue 对不同 alt AA 的 exact values；overview 不画 19 个圈。

### 5.6 Sequence track 的推荐排布

```text
Canonical navigator        full-length rail · brush · exact range

VARIATION
  Variant density          64 screen bins → cluster → residue

PROTEIN FEATURES
  Pfam/domain              intervals
  Topology/membrane        intervals with distinct texture
  Secondary structure      helix capsules · beta arrows · turns
  Functional sites         bounded symbols

MOLECULAR SIGNALS
  PTM                      clustered shape grammar
  Conservation JSD         mean line + min/max band, fixed 0–1
  Predicted stability      median/IQR around zero
  Covalent pairs           linked endpoints

Selected site dossier      exact values · source-specific evidence · actions
```

Variation / Protein features / Molecular signals group toggle 与 preset 仍是后续可选增强；当前已完成的各 track 保留独立、可发现的交互与 selected-site context。

### 5.7 面向任务的快速入口

八条 track 默认等权会增加决策负担。建议提供四个可恢复的显示 preset，同时保留逐 track 开关：

| preset | 默认 tracks | 回答的问题 |
|---|---|---|
| Variant landscape | Variant、Topology、Domain、strict P/LP marker | 变异集中在哪些 canonical 区域？ |
| Regulation & sites | PTM、Functional、Conservation、Secondary structure | 哪些功能/修饰位点与结构特征共定位？ |
| Stability effects | Stability、Variant、Domain | 预测 ΔΔG 在哪些区域变化？ |
| All evidence | 全部可用 tracks | 完整探索 |

顶部显示来源内 exact summary，例如 `4,381 variants across 1,190 canonical sites`、`136 PTM records at 129 sites`；它们是导航入口，不是综合优先级。切换 preset 不清除 pinned site，URL 可恢复 mode/range/site。

### 6.1 为什么当前显得“淡且都是蓝色”

当前 section 虽有不同 `--section-accent`，但大面积仍由 7–11% tint + 白色组成，且多个 accent 本身是浅蓝/浅绿；用户看到的是相似的 pastel surface，而不是清楚的 module identity。

修正方式不是给每张卡铺高饱和背景，而是提高**边界、标题、icon 和 active state**的色彩浓度：

- section rail：100% accent，4–5 px；
- section icon tile：15–22% tint + 100% dark glyph；
- heading/body 仍是 ink；
- card border：35–45% accent mix；
- section background tint：6–10%，只用于 header/selected row；
- primary interactive button：实色 `#005F73`；
- focus ring：`#EE9B00`，不作为数据色。

### 6.2 四任务组

| Genetic evidence | burnt caramel `#CA6702` | oxidized iron `#AE2012` | peach `#FFC1A6` | Variants、ClinVar/COSMIC actions |
| Molecular context | dark cyan `#0A9396` | dark teal `#005F73` | pearl aqua `#94D2BD` | Anatomy、Expression、QTL、AlphaGenome |
| Network & clinical | golden orange `#EE9B00` | brown red `#9B2226` | vanilla `#E9D8A6` | Interactions、Disease |

四组颜色用于定位和导航，不用于跨来源科学结论。

### 6.3 section 内色阶

每个 section 采用五个 role，而不是任意 hex：

```text
--section-50    轻背景，只占小面积
--section-100   icon tile / selected row
--section-400   border / inactive glyph
--section-600   active button / rail
--section-800   heading / dark icon
```

同一任务组内不同 section 通过 hue/明度变化区分，例如：Sequence `#457B9D`、Structure `#0A9396`；Expression `#67A583`、QTL `#005F73`、AlphaGenome `#7B95C6`。不要继续让所有 section 都回退到同一个浅蓝 soft background。

### 6.4 科学色阶独立

| 数据 | palette | 规则 |
|---|---|---|
| Variant total | golden orange | count/density，不表示 pathogenicity |
| strict ClinVar P/LP presence | oxidized iron + triangle/text | 只表示 explicit source presence，不表示 consensus |
| PTM | categorical + shape | 类型 family，不表示强弱 |
| JSD | `#CAF0F8 → #0077B6 → #03045E` | fixed 0–1 sequential scale |
| Stability | `#005F73 ← neutral → #CA6702/#AE2012` | signed diverging around zero，单位 kcal/mol |
| pLDDT | AlphaFold official four bands | confidence，不是 B-factor 或 quality score |
| Expression | modality-specific | HPA RNA/MS/IHC/PaxDB 不共享 quantitative scale |

### 6.5 对比与可访问性

- 正文/metadata 均需通过 WCAG AA；浅色 chip 内使用 ink/deep text，不使用白字。
- 任何红绿/蓝橙数据都增加 shape、sign、label 或 pattern。
- focus ring 2–3 px，所有 Canvas/SVG 图形有键盘等价入口和可见 readout。
- `prefers-reduced-motion` 关闭平移、缩放和自动 spin 的过渡；状态变化仍即时可见。

## 8. 前端架构深化候选

本轮重点不是把大组件机械拆小，而是让高复杂度规则集中在少数 deep Module；一个仅转发 props 的文件是 shallow，不能通过 deletion test。

### Candidate A：Sequence screen-space LOD Module — Strong / top recommendation

- Problem：variant、PTM、stability 在不同组件内各自决定绘制粒度；全长与 detail 的切换规则分散。
- Module：集中 viewport→display level、bin/cluster aggregation、hit testing、keyboard traversal 和 `Showing X of Y`。
- Leverage：Variant、PTM、JSD、Stability、secondary structure 共享一次 zoom/coordinate decision。
- Locality：所有 canonical bin 边界、display thresholds 和 aggregation semantics 在一个 Implementation 中。
- Deletion test：若删除，至少 Variant/PTM/Stability 三个调用者都要重新实现 LOD 和 hit testing，因此具备 Depth。
- 主要 touchpoints：`components/sequence-explorer.tsx`、`lib/sequence-navigator.ts`、新增纯函数模块、`app/styles/sequence.css`。

### Candidate B：Canonical annotation track Module — Strong

- Problem：生成数据已将 feature 分为 topology、domain/region、secondary structure、functional site 等类别；secondary structure 已完成从查询、Pydantic、TypeScript 到 React/CSS 的纵向切片，后续新增 track 仍不应复制这套路由规则。
- Module：集中有限且明确的 canonical annotation catalog、track order、来源说明、shape grammar 和 empty state；不建设任意插件系统。
- Leverage：Sequence、Selected Site dossier 和后续 Structure hover 可复用同一 annotation semantics。
- Locality：Helix/Beta/Turn、Pfam/UniProt domain、Topology 与 Functional site 的科学分类不散落在多个 renderer。
- Deletion test：删除后数据路由、shape、legend、source label 会跨后端和前端重新复制，具备 Depth。
- 主要 touchpoints：`config/feature_track_map.json`、`backend/app/m2.py`、`backend/app/models.py`、`frontend/lib/api.ts`、Sequence renderer/tests。

### Candidate C：Tissue visual mapping Module — Strong

- Problem：47 个区域的 system/icon/anatomogram/fallback 若散落在 Anatomy、Expression、GEN、QTL，会发生视觉和术语漂移。
- Module：以现有 exact `body_region_id` 为输入，集中 system 分组、Healthicons key、specific/system fallback、EBI target availability 和 accessible label。
- Leverage：四个 tissue-aware section 共用一套规则。
- Locality：crosswalk 仍保留 raw mapping，视觉 metadata 在 website-owned config 中单点维护。
- Deletion test：删除后四个页面都必须复制相同判断，具备 Depth。
- 主要 touchpoints：`config/anatomy_crosswalk.json` 或并列 visual config、`anatomy-navigator.tsx`、Expression/GEN/QTL tissue controls、local SVG assets。

### Candidate D：Structure selection Module — Strong

- Problem：ProteinOverview、Structure、DBREF mapping、fragment switch 和 Mol* focus 已形成 shared selection locality；下一步只需在 GPU 浏览器完成真实 picking/focus QA，不应重新拆分状态。
- Module：集中 canonical site/range、fragment coverage、local↔canonical mapping、selected/readout/not-mapped state。
- Leverage：Sequence、Structure、Variant filter 和 Selected Site dossier 共用一个 selection。
- Locality：mapping error 不在各 UI 重复处理。
- 重要约束：当前只有 Mol* 一个 production implementation，不创建无第二实现支撑的通用 viewer Adapter。
- 主要 touchpoints：`protein-overview.tsx`、`structure-panel.tsx`、`structure-viewer.tsx`、`lib/structure-colors.ts`。

### Candidate E：Scientific visual tokens — Worth exploring

- Problem：section theme 与科学数据 hex 混在局部 CSS，调整一个 palette 时影响面难以判断。
- Module：CSS 层分成 UI role、section identity、source identity、scientific scale、state 五类 token。
- Leverage：全部 section、legend、button、Canvas/SVG color functions 获得一致命名。
- Locality：科学语义颜色仍由各数据 module 解释，不建一个把所有数据混为一谈的 palette registry。
- 主要 touchpoints：`tokens.css`、`section-themes.css`、`sequence.css`、`sequence-track-colors.ts`、`sequence-stability.ts`。

### 明确拒绝：统一 icon registry — Speculative / do not build now

一个动态 icon registry 会把 Lucide、Healthicons、科研插图、source state 混成宽泛 Interface，调用者仍需理解所有差异，是 shallow abstraction。当前只需要：命名 import 的 Lucide、受控 tissue metadata、静态 asset manifest；不建设插件化 icon system。
